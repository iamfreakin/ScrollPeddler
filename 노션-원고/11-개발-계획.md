## 진행 방법

할 일은 Backlog 태스크 하나가 기준입니다. 태스크마다 출처 문서, 완료 조건, 선행 작업이 적혀 있습니다.

| 순서 | 하는 일 |
| --- | --- |
| 1. 고르기 | `backlog board`(터미널) 또는 `backlog browser`(웹 칸반)에서 선행 작업이 끝난 To Do 중 우선순위가 가장 높은 것을 고른다 |
| 2. 시작 | 태스크를 In Progress로 옮긴다. 한 번에 하나만 진행한다 |
| 3. 계획 | 무엇을 만들지 애매하면 superpowers의 brainstorming, 단계가 여럿이면 writing-plans로 계획을 세워 태스크의 Implementation Plan에 적는다 |
| 4. 구현·확인 | 완료 조건을 하나씩 확인한다. 수량·문장 계산·반응 순서·효과 수명·중복 요청은 자동화 테스트로, 패키지 접속·물리 이동·재미·원인 이해는 사람이 직접 본다 |
| 5. 마무리 | 빌드 ID·로그·기록 같은 증거를 태스크 노트에 남기고 Done으로 옮긴다. 커밋은 사용자가 직접 한다 |
| 6. 막힐 때 | 같은 원인으로 세 번 막히면 기능을 더 쌓지 않고 원인·남은 결함·필요한 작업일을 태스크 노트에 남긴다 |

각 단계는 **판정 태스크**로 끝납니다. 판정을 통과해야 다음 단계의 첫 태스크가 열립니다. 판정이 실패해도 그 결론이 유효한 결과입니다.

| 전체 분량 | 필수 엔딩과 전체 경험을 따로 기록, 약 10시간 목표 | 반복 강요보다 새 판단이 없는 콘텐츠를 고치고 중복 시간 제거 |

참고작이 있다는 사실은 위 표의 통과 결과가 아닙니다. 열·젖음·탄성 완충·여과 속도는 실제 단위를 정한 뒤 확인합니다. 상세 판정은 [W14 의뢰 판정·납품 규격](../claude-lead/W14-의뢰판정-납품규격.md)과 [W15 레퍼런스 36작품·적용 근거](../claude-lead/W15-레퍼런스36-적용근거.md)를 함께 봅니다.

## 줄이거나 멈출 때

| 상황 | 대응 |
| --- | --- |
| 일정 초과 | 장식/상점 → 축제 → 사진기 → 꾸미기 종류 순으로 줄인다(Backlog 라벨 `컷후보`). 전용 모델 대신 기존 소품·동작을 재사용한다. 줄인 뒤 분량을 다시 잰다 |
| 10시간 초과/부족 | 필수 엔딩과 선정 전체를 따로 잰다. 전 상품 양산·210문장 전수 시험·무한 발주로 분량을 채우지 않는다 |
| 핵심 실패 반복 | 같은 핵심 검증 3회 실패, 단가 상한 2회 초과, 데모 전 예비 절반 소진이면 범위와 일정을 다시 본다 |
| 끝까지 지킬 것 | 원인 설명, 맨손 수습, 공방/탐험 비중, 물 취약·출입 규칙, 저장 신뢰, 개인 참여의 사실성 |

새 지역·새 룬·음성 인식 주문·자동 호스트 이전은 출시 뒤 후보이며 약속이 아닙니다.

## 공개·가격·현지화

공개 순서는 슬라이스의 실제 영상·목표 그림체·하루 흐름 → 스토어 페이지와 짧은 클립 3개 → 비공개 테스트 → 공개 데모 → 1.0입니다. 75초 트레일러는 제작 판단·정상 작업 사고·손 수습·고객 결과를 실제 빌드로 보여 줍니다. 실측 전에는 10시간을 광고하지 않습니다. 가격은 $12.99 중심 후보이고 목표 PC 사양은 슬라이스 때 정합니다. 행사·플랫폼 정책은 등록할 때 공식 자료로 다시 확인합니다. 업적·축제·광고 규칙은 [T7 §4](../claude-lead/T7-프로덕션.md), 데모·스토어·트레일러 상세는 [W12](../claude-lead/W12-출시준비.md)에 있습니다.

현지화는 한국어 원문 표 → 용어를 고정한 초벌 번역 → 사용자 검수 → 게임 안 길이·줄바꿈 → 영어권 검수 순서입니다. 룬은 Glow/Stick/Pull/Bounce/Heat/Blot/Filter, 대상 Thing/Floor/Wall/Me/You/Around, 수식 Brief/Long/Wide/Hard/Far입니다. 상태·예약·사실·추정의 구분은 번역에서도 지킵니다. 용어집은 [W09](../claude-lead/W09-현지화-영문용어집.md)에 있습니다.

## AI 도구 사용 원칙

| 원칙 | 내용 |
| --- | --- |
| 최종 손질은 사람이 | Meshy 초안을 Blender에서 다듬고 스타일·기능을 확인 |
| 기록 | 도구·생성일·원본·라이선스를 에셋 대장에 기록 |
| 라이선스·고지 | 요금제별 상업 이용 원문·Steam 최신 고지 규정 확인 |
| 프롬프트 | 다른 게임/작가 이름 대신 형태·색·조명을 풀어 씀 |
| 입력 자료와 보안 | 권한 없는 이미지·음향·코드, 타인의 개인정보·플레이테스터 기록·계정 정보, 비밀키·토큰·접속 정보·비공개 빌드, 계약·재무·외주 조건 등 비공개 사업 자료는 외부 AI 서비스에 입력하지 않습니다. 미공개 소스 코드나 제작 자료는 보존·학습·접근 조건을 확인한 서비스에만 필요한 최소 범위로 입력합니다 |
| 출시 전 검수 | 플레이어에게 노출되거나 출시 빌드에 포함될 AI 산출물은 담당자와 중앙 검수자가 권리·보안·게임 적합성, 실제 플레이 환경의 기능·성능·접근성·재현성, 사람이 이해하고 수정·대체할 수 있는지를 확인합니다. 모델·주요 입력·노출 방식·사용처가 바뀌면 재검수합니다 |
| 실시간 생성형 AI | 초기 출시 범위에는 게임 실행 중 콘텐츠를 생성하는 AI를 포함하지 않습니다. 도입하려면 별도 설계 문서에서 안전장치·비용·장애 대응·플랫폼 고지를 정의하고 중앙 승인을 다시 받습니다 |
