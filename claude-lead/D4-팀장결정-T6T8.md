## T6 — 내러티브

| ID | 결정 | 이유 |
|---|---|---|
| D4-01 | **채택.** 옛 제작자는 한 명의 천재가 아니라 **여러 세대가 고쳐 온 생활 도안의 기록**이다. **악당은 두지 않는다.** 엔딩은 그 도안을 복원해 다시 쓰이게 하는 것. | 우리 톤(밝은 공방·소동 중심)에 맞습니다. 악당을 두면 보스전과 전투 시스템이 따라와 범위가 커집니다. |
| D4-02 | **채택(수정).** 후기 R03의 "독해 부족" 문구는 기본을 **중립 문구**로 바꾼다. 원래의 농담 섞인 문구는 **손님이 스스로 잘못 썼다고 신고한 경우에만** 쓴다. | 플레이어를 놀리는 인상을 피합니다. 손님이 자기 실수를 인정하는 장면은 여전히 웃깁니다. |
| D4-03 | **확인.** "10시간에 모든 콘텐츠"는 인물 9명·모든 지역·필수 이야기·복원 결말을 보는 경로를 뜻한다. 조건부 후기·기사 문구를 전부 보는 것은 아니다. | D3-01과 같은 기준입니다. |
| D4-04 | **확인.** `오래`는 1막에서, 필요한 의뢰를 수락하기 전에 배운다. | T0 정정 v0.1과 같습니다. |
| D4-05 | **신규.** 축소안에서 지역이 3곳이 되므로, **4막의 무대는 새 지역이 아니라 기존 지역의 잠긴 심층부("옛 제작자의 공방")**로 만든다. | 지역을 하나 줄이면서도 4막이 성립합니다. 이미 배운 공간을 다르게 쓰는 편이 제작비도 적습니다. |

## T8 — 기술 설계

| ID | 결정 | 이유 |
|---|---|---|
| D4-06 | **확인.** 지연 발동은 주변 중심 = 발동 시 시전자 위치, `넓게`의 대상 목록 = 발동 시 계산, 단일 대상·표면은 찢을 때 잠금. | D1-08과 같습니다. |
| D4-07 | **확정.** `당겨라`의 기준점은 **찢기 승인 시 위치**로 고정한다. 지연 뒤 범위 이탈도 이 기준점에서 잰다. | 기준점이 하나여야 화면에서 당김선이 거짓말을 하지 않습니다. |
| D4-08 | **결정.** 밸런스 수치가 바뀌면 **이미 만든 제품도 최신 수치를 따른다.** 자료에 `ContentRevision`을 남긴다. | 재고에 옛 수치 제품이 섞이면 "왜 이렇게 됐지"를 설명할 수 없습니다. 우리 게임의 제1원칙은 원인을 읽을 수 있는 것입니다. |
| D4-09 | **채택.** 기술 구조는 **실행 모듈 1개 + 표 중심 정의 + 공통 Component + 서버 거래·반응 큐**로 시작하고, 필요할 때 편집기 검증 모듈을 추가한다. | 1인 개발에 맞는 최소 구조입니다. |

## 통합 때 확인할 것
- D4-05(4막을 기존 지역 심층부로)를 T3 레벨안과 T5 해금표에 반영.
- T6의 집필량(본편 이야기 약 560~650문장 + 공통 조각 80항목)을 T7 일정에 이미 반영했는지 확인.
- T8의 저장 형식이 T1의 저장 규칙(D1-04·D1-05)과 맞는지 확인.
