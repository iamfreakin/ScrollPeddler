**확인 범위:** 조사한 공식 자료로는 고객이 산 물건을 매번 눈앞에서 쓰는 연출, 아군 방해 직후의 면역, 게스트가 호스트 진행을 자동으로 복사하는 규칙을 입증하지 못했다. 해당 기능은 원작의 규칙이라고 적지 않는다. 아래의 짧은 고객 사용 장면·반복 방해 제한·게스트 기록은 우리 게임의 필요에서 나온 설계다.

## 2. 개선 목록과 완료 조건

기존 기능을 새로 없는 것처럼 취급하지 않는다. 자유 시험·다른 정답·4공정·상태 변주·후기·개인 발견 기록·꾸미기 지출처는 이미 있다. 이번에는 반복 플레이에서 이 기능들이 실제 판단으로 이어지게 구체화한다.

| ID | 개선할 것 | 기존 기능에 더할 내용 | 완료 판단 |
|---|---|---|---|
| R01 | 재주문의 판단 | 같은 용도에 변경 조건 하나와 도안 비교 | 저장 도안이 여전히 맞는지 플레이어가 설명함 |
| R02 | 출발 준비 | 주문용·탐험용·판매 가능 재고를 한 화면에서 비교 | 무엇을 남길지 이유를 들어 고름 |
| R03 | 공방 기여 | 공정마다 작은 선택, 물건 이어받기, 편한 배치 | 숙련자 외의 사람도 자기 판단을 한 번 이상 함 |
| R04 | 자연스러운 협동 사고 | 정상 작업 두 개가 같은 공간에서 충돌하는 장면 | 고의 방해 없이 사고가 생기고 원인을 설명함 |
| R05 | 방해 피로 | 맨손 수습 뒤 재부여 보호를 작은 범위로 시험 | 같은 동료에게 즉시 반복해서 묶이는 상황이 줄어듦 |
| R06 | 탐험 변주 | 기존 13개 상태가 유리한 경로·도구 선택을 바꿈 | 익숙한 방에서 준비나 경로를 다시 고름 |
| R07 | 잔향의 깊이 | 중후반 3개는 사고를 멈춘 뒤 작업을 다시 성립시킴 | 왜 고쳤는지 행동과 결과로 설명함 |
| R08 | 제작자의 보람 | 고객 사용 3장면, 문장에 맞는 후기, 다음 부탁 | 자신이 판 제품과 결과를 연결해 기억함 |
| R09 | 첫날 개인 경험 | 각자 조립·사용·수정, 이후 공동 인쇄·납품 | 한 명이 튜토리얼을 대신 끝내지 않음 |
| R10 | 필요한 의사소통 | 1일차부터 재료명·필요량 요청 | 음성 없이도 필요한 재료와 수량을 전달함 |
| R11 | 게스트의 남는 것 | 기존 개인 기록에 제작·발견·참여를 표시 | 다른 공방에서도 자신의 경험을 다시 볼 수 있음 |
| R12 | 엔딩의 자기 기록 | 실제로 확인한 작업 조건 한 줄을 복원본에 남김 | 복원본에 파티가 한 행동이 정확히 남음 |
| R13 | 엔딩 뒤의 목적 | 미완료 과제와 익숙한 기능의 새 조건을 모아 보여 줌 | 다음에 할 일을 스스로 고를 수 있음 |
| R14 | 규칙의 일관성 | 판매 한도·물때·생물 떨굼·대사 충돌 정리 | §10의 모순이 구현 기준에 남지 않음 |

## 3. 주문과 도안 — 저장한 판을 다시 살필 이유

### 3.1 손님의 문제를 제작 조건으로 바꾸기

[사실] Potion Craft는 고객의 문제를 듣는 선택과 제작법 저장을 함께 둔다. 이를 참고해, Scroll Peddler의 재주문도 저장한 판을 그대로 써도 되는 날과 손봐야 하는 날을 섞는다. [공식 설명](https://blog.playstation.com/2022/12/21/potion-craft-is-coming-to-playstation/)

[추천] 주문은 **필요 효과 + 사용할 대상 + 바뀐 조건 하나**로 읽는다. 기획자가 적는 허용 조건으로 판정하며, 자유 문장을 인공지능이 해석하는 방식은 쓰지 않는다. 손님 설명과 검사 틀이 같은 조건을 가리켜야 한다.

| 단계 | 적용 규칙 |
|---|---|
| 기본 주문 | 현재의 고유 의뢰 32건과 다른 정답 허용을 유지 |
| 재주문 | 첫 완료 뒤 3~5일, 하루 1건이라는 기존 범위 안에서 생성 |
| 변경 빈도 | 재주문 3번 중 1번에 조건 하나를 바꾸는 값으로 시작. 이미 아는 룬으로 풀 수 있는 경우만 등장 |
| 알림 | 주문지에서 이전 주문과 달라진 부분 한 줄만 표시. 저장 판의 적합 여부와 이유를 검사 틀에서 확인 |
| 보상 | 기존 `q × F + B`를 사용. 더 비싼 문장이 필요한 변경이면 수락 전 총 보상도 다시 계산 |
| 거절·보류 | 조건이 어렵다면 다음 날로 넘김. 억지로 출발하거나 미지 룬을 먼저 찾도록 강요하지 않음 |
| 시험 | 무료 시험은 유지. 비교하려는 문장을 바로 시험판으로 보내고 적합성 확인 뒤 실제 인쇄 |

다음은 [추천] 재주문 예시다. 추가 인물이나 고유 의뢰 ID는 만들지 않는다. 효과 지속·범위는 기존 룬 계산을 사용한다.

| 기존 용도 | 바뀐 조건 | 가능한 판단 | 판정할 값 |
|---|---|---|---|
| 에다의 짐 조명 | 오늘은 한 구간이 3분으로 길어짐 | 잠깐의 빛 60초로는 부족해 오래 360초로 바꿈 | 물건 대상, 빛 지속 180초 이상 |
| 보린의 부품 고정 | 오늘 부품은 12초 동안 잡고 있어야 함 | 잠깐 4초 대신 오래 24초. 범위 확대는 필수가 아님 | 물건 대상, 접착 지속 12초 이상 |
| 무로의 바닥 표식 | 오늘은 이동하는 상자에 표시를 붙여 달라. 유지 시간은 그대로 | 바닥 대상의 기존 판 대신 물건 대상으로 변경 | 물건 대상, 빛 지속 360초 이상 |
| 이솔의 이동 여과틀 | 이번 작업은 가루가 지나는 15초만 막으면 됨 | 물건 대상은 그대로. 오래 판을 재사용하거나 잠깐으로 먹을 아낄지 선택 | 물건 대상, 여과 지속 15초 이상 |
| 카엘의 물건 회수 | 얕은 수로 건너 8m 선반에서 회수해야 함 | 멀리의 사거리가 필요. 세게는 사거리를 늘리지 않음 | 물건 대상, 당김 사거리 8m 이상 |

같은 이름의 룬 하나만 정답으로 박지 않는다. 조건을 만족하는 문장은 모두 받되, 물건·바닥 같은 대상 구분이 실제 사용 상황에 맞는지 확인한다. 수정 없이 통과하는 재주문도 필요하다. 매번 판을 새로 만들게 하면 저장의 보상이 사라진다.

### 3.2 단골과 후속 부탁

[사실] Potionomics는 이름 있는 인물의 관계를 새로운 선택에 연결하고, Strange Horticulture는 상품 선택을 이야기와 연결한다. [Potionomics 공동창업자 인터뷰](https://www.gamedeveloper.com/business/how-potionomics-turned-price-haggling-into-a-card-game), [Strange Horticulture 공식 소개](https://store.steampowered.com/app/1574580/Strange_Horticulture/)

[추천] 현재의 9명·32건 안에서 **첫 부탁 → 쓴 결과 → 달라진 다음 부탁**의 연결을 명시한다. 새 호감도 숫자를 추가하지 않고 기존 완료 상태를 사용한다. 후속 부탁이 필요 없으면 사용 요령 한 줄이나 기존 꾸미기 선물로 끝낸다.

## 4. 공방과 협동 — 각자 판단하고 서로 이어받기

### 4.1 네 공정의 선택

### 4.3 정상적인 작업이 만나 생기는 사고

다음 장면은 [추천]이며 기존 접착·열·먹막·탄성 규칙으로 만든다. 사고를 내라고 목표를 주지 않고, 운반·채집·시야 확보라는 정상 목표를 준 상태에서 관찰한다.

| 장면 | 서로 합리적인 두 행동 | 예상 사고 | 동료의 수습 |
|---|---|---|---|
| 광차 정지 | A는 굴러가는 광차를 접착 바닥으로 멈춤. B는 뒤에서 짐을 내리려 접근 | 같은 바닥을 밟은 B도 붙음 | 맨손으로 떼기. 열을 쓰면 광차도 다시 움직일 수 있음을 보고 받침·정지 위치 선택 |
| 어두운 방의 채집 | A는 동료를 밝혀 작업등으로 씀. B는 먹물도롱뇽의 떨굼을 유도 | 먹 분출이 작업등 역할의 동료를 덮어 어두워짐 | 먹막을 손으로 닦고 S3를 확인. 빛을 새로 써도 막을 닦기 전에는 가려져 있음 |
| 통 회수 | A는 경사 아래 통을 당김. B는 충돌을 줄이려 통에 탄성을 줌 | 당겨온 통이 작업대와 새로 충돌해 되튐 | 기존 접착 구간으로 멈춤. 탄성은 멈춘 통을 저절로 발사하지 않음 |

안전하게 끝낸 작업도 성공으로 인정한다. 웃긴 장면만 점수로 보상하면 일부러 작업을 망치는 쪽으로 학습할 수 있다.

### 4.4 반복 방해를 줄이는 작은 보호

[사실] 현재는 아군 위험 게이지 상한과 맨손 수습이 있지만, 그것만으로 접착·먹막·당김의 반복 방해를 모두 막는다고 볼 수는 없다. 기존 규칙도 뗀 접착막이 바로 다시 붙는 것은 막는다(원고 02).

[추천] **동료가 만든 접착·먹막을 손으로 제거한 뒤, 그 상태가 제거된 플레이어에게 같은 상태를 동료 문장으로 다시 걸기까지 2초 간격**을 시험한다. 자기 손으로 뗐든 다른 동료가 대신 뗐든 보호받는 쪽은 막에서 풀려난 플레이어다. 같은 막의 재접촉과 새 문장의 재부여를 구분해 검사한다. 해당 보호 중에는 대상의 작은 종이 표시로 이유를 보여 주고, 마법을 무작위로 실패시키지 않는다. 생물의 공격·환경 위험·자기 문장까지 보호하는 전면 면역으로 확대하지 않는다.

당김으로 계속 끌리는 문제는 별도 관찰한다. 먼저 다른 사람이 쓰기 전 당김 예고를 읽는지와 같은 시점 중복 적용을 확인하고, 제어를 잃는 반복이 남으면 아군 당김에도 해제 후 간격을 적용할지 정한다. 보호는 우리 게임의 피로 완화안이며, 조사한 협동 게임의 확인된 규칙을 복제한 것이 아니다.

### 5.3 공동 수정 기록을 직접 알아차리기

[추천] 인물의 설명 전에 플레이어가 서로 다른 필체의 기록 두 장을 같은 곳에서 비교하는 장면을 둔다. 한 장에는 실패한 문장, 다른 장에는 바뀐 대상·손 작업이 적혀 있다. 플레이어가 현장에서 시험해 결과를 확인하고, NPC는 이미 확인한 의미를 짧게 정리한다. 이야기의 악당·분기 엔딩은 추가하지 않는다.

|---|---|---|
| 공방 재고 | 현재 사용 가능한 재료·먹·봉인품 | 기존 재고 읽기 |
| 주문에 필요 | 수락한 주문의 남은 문장을 만들 양 | 실제 선택한 문장의 먹 비용으로 계산 |
| 탐험에 남길 것 | 내가 선택한 6장·손판 2문장의 준비에 필요한 양 | 플레이어가 예약을 켜고 끔 |
| 추가로 필요한 양 | 위 두 목표를 함께 하려면 모자라는 양 | 요청 표시 또는 발견한 산지 확인 |

같은 재료를 두 용도로 중복 예약하면 부족량을 알린다. 이 절의 예약은 **주문·출발 계획용 표시**다. 다른 사람이 그 계획분을 쓰려면 한 번 확인한 뒤 계획표와 공용 재고를 함께 갱신한다. **이미 인쇄를 시작한 묶음의 확정 예약분은 다른 용도로 소비할 수 없다.** 시작 당시 도안·재료를 유지하고 취소 때 아직 안 쓴 몫만 풀리는 기존 규칙을 따른다(원고 09). 던전 전리품은 준비 목표에 도움이 되는지 보여 주되 아직 발견하지 않은 산지를 미리 공개하지 않는다.

[사실] Moonlighter가 확인시켜 주는 것은 판매·장비 제작·운반 선택의 연결이다. 모든 전리품이 제작재료라는 주장까지 확대하지 않는다. 위의 공방 주문과 탐험 스크롤의 공유 재고는 Scroll Peddler 자체의 구조를 구체화한 것이다. [Moonlighter 공식 소개](https://store.steampowered.com/app/606150/Moonlighter/)

### 6.2 몬스터 먹의 보충 구매

[사실] W07 §6.2의 1인 3~4주차 몬스터 먹 수요는 약 12~13회분/주이고, 상인 한도는 파티 공용 하루 2회분이다. 5일 동안 한도를 모두 살 수 있다면 10회분이다.

[추정] `10 ÷ 12~13 = 약 77~83%`다. 필요한 종류의 재고와 구매 자금이 있다는 조건의 최대 보충 비중이다. 실제 구매율·탐험 생략률을 측정한 값이 아니며, 새 룬은 여전히 던전에서만 얻는다.

[추천] 첫 경제 검증값은 **하루 2회분 + 5일 주간 합계 5회분**, 파티 공용으로 둔다. 급한 날 2회분을 살 수 있는 편의는 유지하면서 주 전체 수요를 대체하기 어렵게 한다. 12~13회분에 대한 최대 비중은 약 38~42%다. 종류별 한도가 아니라 몬스터 먹 3종 합계이며, 주간 신문이 나오는 5일 구간에 맞춰 초기화한다. 구매가와 일반 재료·부재료의 비상 구매는 우선 그대로 둔다.

**조정 원칙:** 주문이 반복해서 막히면 상한부터 무조건 낮추지 않는다. 출현·떨굼·필수 사용량·재주문 빈도를 함께 확인한다. 1~4인에서 재료 공급/실제 소비 1.0~1.15라는 기존 목표를 별도로 검사한다. 가격 조정·상인 한도 조정은 그 다음이다. 이 주간 한도는 레퍼런스의 숫자를 가져온 것이 아닌 우리 수급표에서 나온 시작값이다.

후반 꾸미기 지출처 약 3,960G와 저축 허용은 유지한다(W07 §7). 현금이 남는다는 이유만으로 빚·세금·필수 유지비를 만들지 않는다.

### 6.3 주문과 자유 판매의 한도 분리

[사실] W07의 전체 판매 4·6·8·10장 한도와 A06의 기본 5장은 동시에 만족하기 어렵다. [추정] 총량을 인원 배수로 올리기만 해도 협동 8·10·13장이다. 같은 날 M10도 예정되어 있다. 조건을 충족한 주문을 판매 한도로 잘라 버리면 납품량·보상·이야기 날짜가 서로 어긋난다.

[추천] 가장 작은 해결은 **계약 납품량과 진열 판매 수요를 분리**하는 것이다.

| 항목 | 적용 규칙 |
|---|---|
| 고유 의뢰 | W07의 문장별 q를 유지. 인원 배수 1·1.5·2·2.5로 문장별 장수를 계산한 뒤 올림. 납품 수량을 판매 상한으로 다시 자르지 않음 |
| A06처럼 여러 문장인 주문 | 각 문장 줄을 별도로 계산. 기본 3+1+1장은 2인 5+2+2=9장, 3인 6+2+2=10장, 4인 8+3+3=14장으로 표시 |
| 재주문·화제·반복 계약 | 정해진 발주 수와 q·B로 제한. 모두 계약 납품으로 셈 |
| 자유 판매 | 원래 예상 사용 범위인 1인 0~2장에서 시작. 수요 상한을 인원별 2·3·4·5장으로 표시. 초과분은 재고로 남음 |
| 분할 납품 | 상자에 적합품을 저장하고 다음 날 이어서 납품 가능. 완료 때 B·평판을 한 번 지급 |
| 수입 목표 | 기존 매출·말일 현금 추정은 재검산 전 값으로 표시. 한도 변경 뒤에도 옛 수입 목표를 검증 완료라고 쓰지 않음 |

**올림 기준은 이번에 명확하게 정한 추천이다.** 기존 문서는 혼합 주문을 합산한 뒤 올릴지 각 문장별로 올릴지 불명확했다. 문장별 올림은 부족한 줄 없이 납품할 수 있지만 합산 올림보다 협동 수요가 늘 수 있다. 주문·수급표를 갱신할 때 반드시 이 방식으로 계산한다.

§6.2의 12~13회분은 기존 1인 수급표라 위 협동 올림과 섞어 쓰지 않는다. 재계산에는 고유 의뢰, 재주문, 자유 판매, 탐험 사용, 파손을 모두 포함하고, 공급은 실제 안전 반출과 실제 구매만 센다.

### 6.4 광차와 물때의 역할

[사실] 물에 강한 미반출 재료는 바닥·가방 모두 같은 판정으로 입구에서 공동 회수한다. 물 취약 3종과 미봉인 급조품만 잃고, 봉인품·돈·룬·도안은 보존한다. 이는 기존 사용자·팀장 결정이며 유지한다(원고 02·04, L07~09).

[추천] **광차의 입구 도착은 정상 조기 반출, 물때의 공동 회수는 하루 종료 시 안전 회수**로 명칭과 시점을 구분한다.

| 상황 | 재료 결과 | 광차·운반의 의미 |
|---|---|---|
| 12분 전에 입구에 전달 | 전달한 재료는 반출 완료. 먼저 나온 동료가 공방에 가져가 가공 가능 | 가방보다 많은 짐을 운반하고, 공방 제작을 먼저 시작함 |
| 현장에 짐을 두고 먼저 귀환 | 남은 짐은 그날 탐험이 끝날 때 정산. 그 전에는 공방에서 사용할 수 없음 | 준비된 동료에게 가져와 달라고 요청할 이유 |
| 물때 종료 | 이미 획득해 가방·손·바닥·광차에 있는 짐에 동일 판정. 강한 재료는 공동 회수, 약한 재료·미봉인 급조품은 파손 | 약한 재료를 제때 옮기고 공방 시간을 확보하는 편익 |
| 자연 채집 지점 | 아직 채취하지 않은 원료는 획득 재료가 아님 | 종료 버튼만으로 미채취 원료까지 생기지 않음 |
| 전원 조기 귀환·응급 복귀 | 현장 잔류품에 물때 결과를 앞당겨 한 번 확정. 강한 재료 보존·약한 재료 파손. 정상 귀환자가 이미 가져온 짐은 모두 보존 | 복구 중인 원정자가 없는 전원 귀환 확정 때 처리. 12분까지 강제 대기하지 않음(D1-03) |

획득 후 내려놓은 강한 재료가 자동 회수되는 안전 규칙은 그대로다. 따라서 **모든 강한 재료를 반드시 운반해야 하는 게임**으로 설계하지 않는다. 강한 재료만 노린 날에는 남은 탐험 시간 활용을, 약한 재료가 있는 날에는 조기 반출을 선택할 수 있다. 12분까지 기다려도 손해가 적다는 이유만으로 새 세금·가방 전체 손실을 붙이지 않는다.

시험지는 기존 규칙대로 시험실 안에서만 유효하고 공방 재고·판매품으로 바뀌지 않는다. 개인 조립은 기존 판틀 2개에서 차례로, 조립을 끝낸 사람의 시험은 병렬로 진행한다. 4인용 판틀 4개를 별도로 만들거나 전원의 긴 연출이 끝날 때까지 강제 대기하지 않는다. 인쇄·봉인은 공동 작업으로 완료해 중복 재료·보상을 만들지 않는다. 붙어라의 손 해제 연습은 초반 시험을 마친 사람이 선택적으로 하고, 아직 안 한 사람은 2일차 짧은 안내로 이어간다.

### 8.2 수량 요청은 1일차부터

[사실] 현재 비음성 핑은 있고, 종이컵 통신은 6일차 장치다. 새 물건을 장비할 때까지 재료 수량 소통을 미루지 않는다.

[추천] 기존 재료·주문·준비 화면에서 한 번 누르면 **“눌림수지 2개 필요 — 주문 준비”** 같은 공용 요청을 만든다. 발견한 재료만 선택하고 직접 수량 수정도 가능하게 한다. 같은 재료 요청은 합치고 목표가 채워지면 완료 표시를 하며, 취소할 수 있다. 맵에는 발견한 곳을 요청할 때만 표시한다. 아직 모르는 산지로 자동 안내하지 않는다.

최초값은 동시 요청 3개·같은 사람이 2초 이내 다시 보내기 제한이다. 글자·재료 문양·수량을 함께 쓰고 색만으로 뜻을 구분하지 않는다. 종이컵은 거리감과 역할극에 쓰는 기존 음성 장치로 남는다.

### 8.3 게스트의 공방일지

[추천] 기존 개인 도안·발견 기록의 화면을 넓혀 다음 항목을 보여 준다. 새 경험치·별도 재화·반복 출석 보상은 만들지 않는다.

| 기록 | 언제 남기는가 | 다음 공방에서의 의미 |
|---|---|---|
| 내가 시험한 문장 | 실제 발동과 시험 결과 확인 | 룬을 아는 공방에서 참고할 수 있는 개인 도안 |
| 원정 공유 발견 | 확인 사건 당시 던전 안에 있던 해당 원정 참가자에게 공유. 직접 조작한 사람도 함께 기록 | “우리 원정이 확인한 사실”로 산지·활용법·기여자 확인 |
| 공동 납품 | 주문 완료 당시 참여 또는 관련 작업 기록이 있을 때 | 누구의 공방·어느 주문을 도왔는지 기억 |
| 캠페인 기념 | 복원 작업·첫 사용·마지막 정산에 참여 | 공방 인장과 자신이 본 복원 기록을 보관 |

호스트의 돈·설비·의뢰 완료·룬 해금은 호스트 세계에 남는다. 게스트 기록에 미지 룬 문장이 있어도 그 공방이 룬을 배우기 전에는 만들 수 없다. 개인 일지는 참가자의 경험을 보존하는 기능이다. DRG의 게스트 진행 전체를 복사하는 규칙으로 근거를 붙이지 않는다.

공방에서 인쇄 중인 사람과 이미 귀환한 사람에게 새 현장 발견을 “내가 본 사실”로 지급하지 않는다. 공용 도감으로 파티의 발견을 열람할 수는 있으며, 개인 일지는 자신의 제작·납품 기여를 남긴다. 원정 안의 동료는 같은 방을 보지 못했어도 공유 발견으로 받되 직접 관찰·조작한 사람과 구분해 표시한다.

### 8.4 발견 기록의 정확성

[추천] 기록은 실제 관찰과 조건에 대한 사실을 짧게 남긴다. “뜨거운 벌레가 닿아 접착이 풀렸다”처럼 사건이 확인된 경우에만 기록하고, 미확인 원리는 도감의 정답으로 미리 채우지 않는다. 서버의 사건 판정으로 기록해 서로 다른 사람에게 상반된 정답이 저장되지 않게 한다. Outer Wilds의 단서 재검토 원리를 가져오는 부분이다. [아트 디렉터가 설명한 우주선 기록](https://news.xbox.com/en-us/2019/05/30/outer-wilds-available-today-xbox-game-pass/)

| 세션 | 첫날 약 30분, 일반 하루 20~40분 목표 | 설명·작업·탐험·대기 시간 각각 |
| 전체 분량 | 필수 엔딩·모든 콘텐츠를 나눠 측정. 후자는 약 10시간 목표 | 선택 활동이 재미로 선택됐는지 분량 채우기인지 |

### 11.2 데이터와 저장에 필요한 작은 확장

이 표는 [추천] 기술 작업 범위다. UE API나 엔진 버전별 구현을 확정한 기술 선택이 아니다.

| 기존 데이터 | 더 기록할 것 | 이유 |
|---|---|---|
| 주문 | 효과·대상·지속·범위·사거리 조건, 문장별 장수, 이전 주문과 달라진 조건 | 검사와 후기·보상이 같은 기준 사용 |
| 판·시험 결과 | 도안 작성자·검증한 조건 | 개인 경험과 적합성 비교 |
| 재고·정산 | 주문·탐험 예약, 획득 여부, 조기 반출/종료 회수, 파손 처리 여부 | 중복 계산·이중 차감 방지 |
| 생물 | 개체별 또는 나방 무리별 그날 떨굼 완료 | 하루 1회 규칙·공급 계산. 개체와 무리의 보상 단위 구분 |
| 고객 사용 | 납품 문장·고객 재고 소비·실제 관찰 여부 | 마법 효과·후기와 장면 일치 |
| 개인 기록 | 확인한 사실·참여한 공방·자기 도안·복원 조건 | 호스트 진행과 게스트 경험 구분 |
| 협동 상태 | 마지막 손 해제 시각·상태 종류·동료 효과 출처 | 반복 방해 보호의 좁은 적용 |

동료에게 보이는 요청·예약·진행은 서버 판정 결과를 공유한다. 저장·재접속 뒤 소비나 완료 보상이 다시 발생하지 않아야 한다. 같은 사건을 정산·도감·후기에 따로 복제해 서로 다른 사실을 만들지 않는다.
